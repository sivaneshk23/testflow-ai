# IBM Bob Usage Plan

## How IBM Bob IDE will be used meaningfully

IBM Bob IDE will be used as the primary environment for planning, creating the controlled demo project, implementing the application, reviewing changes, running tests, debugging failures, and preparing demonstration evidence. Bob use must produce traceable work artifacts rather than being a nominal editor mention.

## Planned task sequence

1. Review and challenge these planning documents in Bob.
2. Create the synthetic demo project and its tests in Bob.
3. Implement policy validation and AST inspection in Bob.
4. Implement controlled execution and JSON evidence handling in Bob.
5. Implement deterministic classification and Streamlit reporting in Bob.
6. Add and run unit, integration, negative, and security tests in Bob.
7. Use Bob to inspect failures, make surgical fixes, and rerun targeted tests.
8. Conduct a final Bob-based review against the compliance checklist.

## Code review process

For each meaningful task, use Bob to inspect the diff, confirm requirement coverage, check for unsafe execution paths, and record review notes or screenshots. Reviewers must verify that no unrelated files or hidden commands were introduced.

## Testing and debugging process

Run the smallest relevant test set first, inspect failures in Bob, preserve the original evidence, fix the root cause, and rerun. Capture screenshots of representative test runs and debugging steps only after they are actually completed.

## Session evidence collection

Maintain Bob session evidence for major tasks: planning review, security-boundary implementation, test execution, debugging, code review, and final demonstration. Evidence should include date/context, action performed, result, and associated file or test, while excluding secrets and personal information. Do not claim Bob contribution without a corresponding session record or screenshot.
