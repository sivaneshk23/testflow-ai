# Data Compliance

## Synthetic data strategy

All demo source files, tests, fixtures, failures, and expected outputs will be authored specifically for TestFlow AI. Examples will use fictional names and non-sensitive values. No production data is needed for the MVP.

## Controlled demo project strategy

- Ship or generate one small local demo project under the approved workspace.
- Keep its dependencies and test commands explicit.
- Permit only configured paths and test identifiers.
- Use deterministic fixtures and intentionally seeded failures for demonstrations.
- Do not accept automatic execution of arbitrary uploaded projects.
- Review every demo file before it is used in a recording or submission.

## Prohibited data categories

- Confidential or proprietary information.
- Client or employer data.
- Personal information or credentials.
- API keys, passwords, tokens, private keys, and connection strings.
- Social-media content or user profiles.
- Unlicensed third-party datasets or copied code not permitted for use.

## Data creation and verification process

1. Author synthetic data and demo code from scratch.
2. Search files and reports for secret-like strings and personal identifiers.
3. Review fixtures, tracebacks, screenshots, and logs before sharing.
4. Confirm that reports contain only synthetic project content and bounded technical output.
5. Record the review date and reviewer in the hackathon evidence checklist without recording personal data in the application.
6. Repeat the review after any demo-project change.
